Instruction Fetch

The fetch stage owns the program counter, the instruction memory address, and the first decision about where execution goes next. In a clean 5-stage design, this stage should stay narrow and predictable so the rest of the pipeline can stay fed.

Architecture Review

What makes the design disciplined

The page is organized around design intent, not screenshots alone. Each block below explains the reasoning that turns a student CPU into a professionally presented project artifact.

Datapath structure

The CPU is framed as a classic instruction path with clearly partitioned responsibility across fetch, decode, execute, memory, and writeback. That structure is useful because it exposes where timing belongs and where control decisions should be made.

  • Program counter and next-PC logic are treated as first-class control objects.
  • Decode is separated from execute so control formation does not get entangled with ALU behavior.
  • Memory behavior is isolated to its own stage rather than scattered across the datapath.

Why TL-Verilog helps here

Timing abstraction reduces the bookkeeping burden that usually appears when a pipeline deepens. That keeps the design focused on architectural intent instead of being dominated by manual register staging.

Professional review angle

The page emphasizes readable partitioning, clean signal ownership, and a credible development flow. That makes the project easier to judge than a raw code dump or screenshot collage.

Expected discussion points

Reviewers can immediately ask about forwarding, branch handling, supported instruction subset, and testing strategy because the page exposes those axes directly.

// timing-abstract CPU structure
|cpu
	@0
		$pc = $reset ? 32'h0 : $pc_next;
		$instr = $imem[$pc[9:2]];

	@1
		$dec_valid = $instr[6:0] != 7'b0;
		$src1_val = $rf_rd_data1;
		$src2_val = $rf_rd_data2;

	@2
		$alu_out = $is_add ? $src1_val + $src2_val :
							 $is_and ? $src1_val & $src2_val : 32'b0;

	@4
		$rf_wr_data = $wb_sel_mem ? $dmem_rdata : $alu_out;
// conceptual RTL partitioning
always_ff @(posedge clk) begin
	if (reset) begin
		if_id_pc    <= 32'b0;
		if_id_instr <= 32'b0;
	end else if (!stall_if) begin
		if_id_pc    <= pc;
		if_id_instr <= instr_f;
	end
end

always_comb begin
	alu_in1   = forward_a_sel ? ex_mem_result : id_ex_rs1;
	alu_in2   = forward_b_sel ? mem_wb_result : id_ex_rs2;
	alu_out   = run_alu(id_ex_alu_op, alu_in1, alu_in2);
	take_br   = branch_check(id_ex_branch, alu_in1, alu_in2);
end

assign wb_data = mem_wb_is_load ? mem_wb_rdata : mem_wb_alu_out;
// lightweight review checklist
assert(pc[1:0] == 2'b00);
assert(!(rf_wr_en && (rd == 5'b0)));

cover(fetch_valid && decode_valid && execute_valid);
cover(branch_taken && !pipeline_flush_error);
